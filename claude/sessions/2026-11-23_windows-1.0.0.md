## 2. Decisions taken in this session

All are in plan §1.
- **M9:** the release version is **1.0.0**.
- **M11:** the app icon uses the Mac's layout at every size. A small-size layout was tried in Phase 4, and you rejected it.
- **M12:** the glyph is **our own headphones drawing**, a rounded band with filled ear cups, for both the tray and app icons. The Mac's SF Symbols headphones can't ship on Windows: Apple licenses SF Symbols for Apple platforms only, and never in app icons.
- **M13:** the tooltip has two lines, "SidetoneOff" and then the status. When sidetone is off, the status reads just "Logitech G635 connected", in the tooltip and in the menu. The menu's status line is always disabled.
- **M14:** "SidetoneOff is running" appears on every start you make, but not at sign-in. The Run value passes `--autostart` to tell them apart.
- **M15–M17:** the log window keeps history in memory only, uses the same lines as the debug log plus a timestamp, and stays light-themed.
- **M18:** the name is **"SidetoneOff"**, one word, everywhere: the Windows UI, folders and registry; the Mac app, including its bundle ID `com.giancarlo.sidetoneoff`; and the repo folder `sidetoneoff`.

## 3. Found during review and testing

- **Tooltip missing until the first status change.** With `NOTIFYICON_VERSION_4`, `NIF_SHOWTIP` must be sent again after `NIM_SETVERSION`, and with every update.
- **`build.ps1 -Install` hung.** `Start-Process -Wait` waits for the whole process tree, and `--install` starts the tray app. Fixed with `Process.WaitForExit`.
- **`taskkill` without `/f`** sends `WM_CLOSE` only to the visible dialog when one is open. Install and uninstall post to the hidden window instead, which closes both.
- **Task Manager › Startup apps** lists every classic startup program on this PC by file name with no publisher, including Edge and Windows Security; ours shows as `SidetoneOff.exe`. For a while it showed proper names, and a restart undid it. That's Windows' behavior; our version info is correct.
- **Tooling gotchas:** in Git Bash, `grep -c $'\r'` counts every line, so count CRs with `tr -cd '\r' | wc -c`. `PrintWindow` captures Task Manager blank. A reboot kills the debug-log listener, but the app's own Show log history covers sign-in.

## 5. Next

1. **The Mac app.** Commit 63b173b renamed it on Windows, so it has never been compiled with the new names.
   - A GitHub Actions workflow on GitHub's Mac machines could build it, as a pre-release, since your Mac is a work machine.
   - The workflow needs a `--no-install` mode in `build.sh`, and possibly a universal build.
   - Without an Apple Developer ID, downloaders must allow the app in System Settings › Privacy & Security › **Open Anyway**.
   - On a Mac that has the old "Sidetone Off.app", uninstall it from its own menu first, because `build.sh` only replaces `SidetoneOff.app`.
   - The plan's backport list in §8 still stands: native IOKit HID with read-back, the wake-from-sleep and HID-arrival triggers, and the drawn app icon.
2. **Linux, on this same machine running Bazzite, and also Kubuntu/Ubuntu.** This is a direction, not a plan yet.
   - **Language:** C++23, reusing `hidpp`, `profile`, `log_history` and their tests.
   - **Headset:** a new `HidrawTransport`. On Linux, the G635's interface 3 is **one** `/dev/hidrawN` carrying all three collections, and HID++ reports start with report ID `0x11`.
   - **System services:** `libsystemd` only. Its D-Bus part (sd-bus) gives the StatusNotifierItem tray, the DBusMenu menu, notifications, and logind's `PrepareForSleep` signal for sleep and wake. Its device part (sd-device) reports plug and unplug, without polling.
   - **Headset access:** a one-time udev rule, which needs your password.
   - **Builds:** made in an Ubuntu 24.04 Distrobox, so the binary also runs on newer distros.
   - **Install:** like Steam, download and double-click. That means a **Flatpak** for Bazzite and KDE, first, and later a **`.deb`** for Ubuntu and Kubuntu. Uninstall from the app store or the tray. Phase 0 must prove two things inside Flatpak's sandbox: asking for the password, and detecting plug and unplug.
   - **Open questions for the plan:** windows and dialogs without a GUI toolkit, the install flow, packaging, and testing.
   - **Where:** the plan goes in `claude/<date>_<n>-linux-1.0.0/`, with this session as input.
